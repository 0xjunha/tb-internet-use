# Program request catalog and code call catalog

The program request catalog is outside knowledge for `extract_network_requests`. It says whether a program fetches, which of its words name what kind of target, where the content it receives goes, and how its options change that. It is filled by hand, its `reviewed` column says which rows a person or three agents have reviewed, and `extract_network_requests` reads it only through `NetworkRequestKnowledge` in [network_request_knowledge.py](../../network_request_knowledge.py). How a program reads its words, e.g. which option takes a value, is not here but in the [program catalog](../expanded_tool_call/README.md) of `expand_tool_calls`, so every program and subcommand here needs a row of `program_behaviors.csv` too.

[`program_network_requests.csv`](program_network_requests.csv) has two kinds of rows, keyed by `program_name`, `subcommand`, `option_name` and `option_value`.

- A program row has a blank `option_name` and is one program and subcommand, e.g. `(pip, install)`. It answers only for an invocation whose `ProgramInvocation.program_name` and `subcommand_words` are those of the row, and a blank `subcommand` is an invocation without subcommand words.
- An option row has an `option_name` and is one option of a program, e.g. `-o` of curl. A blank `subcommand` is every subcommand of the program and a blank `option_value` is every value. For an option of a command `NetworkRequestKnowledge` tries the row of the subcommand and the value first, then the blank subcommand with the value, then the subcommand with a blank value, then both blank, e.g. `(curl, "", -o, -)` before `(curl, "", -o, "")`. An option row needs a program row of the program, or of its subcommand when it names one, that fetches.

A cell holds a fact, a word that stands for a value, e.g. `none` or `no_request`, or a blank. A cell that does not fit the kind of row must be blank, e.g. `option_effect` of a program row or the five cells after `fetches` of a row whose `fetches` is `no`. Among the cells that fit, a blank is unknown only in `content_route`, and `NetworkRequestKnowledge` then answers with `UnknownProgramContentRoute`. Any other blank fact cell fails the load. A program or option whose fact is not known has no row at all, so it stays an unknown input, e.g. an option without a row gives `UnknownProgramOptionEffect` and its request becomes uncertain.

| Column | Row | Cell | Blank |
|---|---|---|---|
| `program_name` | both | The `program_name` of the row of `program_behaviors.csv`, e.g. `pip` | Fails the load |
| `subcommand` | both | The subcommand words split by one space, e.g. `install` or `pip install` of uv | No subcommand words, or every subcommand for an option row |
| `option_name` | option | The option as written, e.g. `-o` or `--no-index` | Makes the row a program row |
| `option_value` | option | The value the row is for, e.g. `HEAD` for `-X` of curl or `-` for `-o` of curl | Every value |
| `fetches` | program | `yes`, `no`, or `only_what_is_missing` when it fetches only what a build or run lacks, e.g. npx, `lake build` or sbt. An install that skips what is there, e.g. `pip install`, is `yes`, since its line `Requirement already satisfied` tells which request was not needed | Fails the load |
| `target_arguments` | program | Which arguments are targets. `all`, e.g. `pip install` or ping, whose words before the last name hosts that the route passes, `first`, e.g. `git clone`, `next_program` for the program it runs, e.g. tsc of `npx tsc`, or `none`, e.g. `apt-get update` | Fails the load |
| `target_kind` | program | A `NetworkRequestTargetKind` value, e.g. `package_name` or `host`, also when no argument is a target | Fails the load |
| `target_notation` | program | A `TargetNotation` value, how a target word names its host, e.g. `url_or_schemeless_url` for curl or `pip_requirement` for pip | Fails the load |
| `target_without_target_arguments` | program | The request when no argument names a target. `no_target` for one without a target, e.g. `apt-get update`, `named_in_file` for one whose targets a file or the project names, e.g. `npm install` or sbt, or `no_request`, e.g. curl alone or `apt-get install`, which without a package fetches only the dependencies that `-f` repairs, or `pip install`, which without a requirement ends with an error. A check that the words do not show, e.g. of a new version of pip itself, is no request of this cell | Fails the load |
| `content_route` | program | Where the content goes before options and redirects change it. `stdout`, e.g. curl, `own_file` for a file the program writes or an install, e.g. wget or `pip install`, or `no_content`, e.g. ping | Unknown |
| `option_effect` | option | A `ProgramOptionEffect` value, e.g. `sends_no_request` for `--no-index` of pip or `names_host_in_value` for `-i` of pip. `none` says that it changes neither whether a request is sent, nor the targets, the hosts or whether the content goes to stdout. `sends_content_to_file` says that the content goes to a file the program writes, e.g. `-o` or `-O` of curl, while `none` fits an option whose file holds something else, e.g. the headers of `-D`. The path of such a file is in `written_files` of the expanded tool call and not here, and when no written file of the command holds it, e.g. f of `curl --output-dir d -o f u`, which is d/f, the content goes to a saved file whose path is not known | Fails the load |
| `checked_against` | both | What the cells were checked against, naming the page, its section and the version, e.g. `git-clone(1) SYNOPSIS and DESCRIPTION, Git 2.56 (git-scm.com)`. A cell taken over from the old program tables without a check says `not checked, from the old table` | Fails the load |
| `reviewed` | both | `yes` once a person has reviewed the row, `agents` once three agents each checked the row against a primary source and all found every value right, two of them seeing the values and one filling them without seeing them | Not reviewed yet |
| `note` | both | Free text, e.g. why a cell is blank | Nothing to note |

A page counts as in the [program catalog](../expanded_tool_call/README.md): a page of the Linux implementation or of the program's own documentation, e.g. a Debian bookworm page on manpages.debian.org or pip.pypa.io, named with its site and version, and never a macOS BSD page for a GNU program.

`NetworkRequestKnowledge.may_program_fetch` answers for a program that code runs, whose subcommand nobody read. It says whether any program row of the name fetches and counts under the key `(program_name, "any subcommand", "", "")`, apart from the counts of the other methods.

A row that `extract_network_requests` cannot use raises `ValueError` when the catalog is loaded, e.g. a filled cell that does not fit the kind of row, a word that no column allows, a blank `checked_against` or an option row whose program has no row that fetches. No script writes the CSV.

## Code call catalog

The code call catalog is outside knowledge for `extract_network_requests` about calls in Python and JavaScript code. It says whether a call sends a request, holds the target of a request that another call sends, runs another program or does none of these, and how its target is written. It is filled by hand, its `reviewed` column says which rows a person or three agents have reviewed, and it is read only through `NetworkRequestKnowledge`.

[`code_calls.csv`](code_calls.csv) has one row per call name of a code language, keyed by `code_language` and `call_name`. `NetworkRequestKnowledge` answers `code_call_label` only for the exact name of a row, e.g. `requests.get`, and `extract_network_requests` picks the name it asks about from the imports of the code text.

| First part of the call name in the code text | Row asked about | What the call becomes | Decided by |
|---|---|---|---|
| Bound by an import, e.g. `u` of `u.urlopen(x)` after `import urllib.request as u` | That of the full name that the import gives, e.g. `urllib.request.urlopen` | A call of the row | The import |
| Bound by an import, and the full name has no row but an end of it has one, e.g. `GPT2TokenizerFast.from_pretrained(m)` after `from transformers import GPT2TokenizerFast` | That of the longest end of the full name with a row, e.g. `from_pretrained` | An uncertain call of the row | `treat_call_name_that_ends_with_catalog_name_as_uncertain_call_of_that_name` |
| Bound by several imports to different full names, e.g. `http` of `import requests as http` in a `try` and `import httpx as http` in its `except` | That of each full name or of its longest end with a row, in the order of the text | An uncertain call of the row of the first full name with one, e.g. `requests.get`, since the text does not show which import ran | The same rule |
| Bound by imports whose full names and their ends have no row, while the name as written or its end has one, e.g. `fetch(u)` after `const fetch = require("node-fetch")` or `new WebSocket(u)` after `const WebSocket = require("ws")` | That of the name as written, else of its longest end with a row | An uncertain call of the row, since a module may give a function under the name of a catalog row | The same rule |
| Bound by an assignment, a parameter or a `for` loop of Python, and the row names a module, e.g. `requests.get(rid)` after `requests = {}` or `ctx.requests.get(rid)` where `ctx` is a parameter | That of the name as written, else of its longest end with a row | A call without a row | `treat_call_of_module_row_through_name_that_code_binds_without_import_as_call_without_row` |
| Bound in the same ways, and the row names no module, e.g. `page.goto(u)` after `page = browser.new_page()` | The same | An uncertain call of the row | `treat_call_name_that_ends_with_catalog_name_as_uncertain_call_of_that_name` |
| Neither imported nor bound, and only an end of the name has a row, e.g. `self.page.goto(u)`, `route.fetch()` or `MyTok.from_pretrained(p)` | That of the longest end with a row | An uncertain call of the row | The same rule |
| Neither imported nor bound, and the name as written has a row, e.g. `fetch(u)` or `subprocess.run(cmd)` after `from helpers import *` | That of the name as written | A call of the row, since the module or function may come from a star import or another part of the code | No rule |
| Any, when neither the full names from imports, the name as written nor an end of them has a row, e.g. `m.compute(x)` after `import mylib as m` | None | A call without a row | No rule |

So a full name that a library documents has a row of its own, e.g. `urllib.request.urlopen`, `huggingface_hub.snapshot_download` or `child_process.execSync`. A bare name that code imports from a module keeps a row beside it, e.g. `urlopen` or `execSync`, for a call whose import the code text does not show, e.g. after `from urllib.request import *` or in `require("child_process").execSync(c)`, and for a call whose name ends with it, e.g. `opener.urlopen(x)`. A method of an object has a row under the variable that its documentation writes the object in, e.g. `page.goto`, or under the method alone, e.g. `from_pretrained`, since no import names the object. An uncertain call of a row that sends a request gives an uncertain request, one of a row that runs a program gives the uncertain requests that any program run by code gives, and one of a row that sends no request is a call without a row, since another function of that name may send one. A row that a rule sets aside or makes uncertain still counts as used, since it decided the call. A call that only builds a client and sends nothing, e.g. `requests.Session()`, has no row, since that it sends a request is no fact and the methods that send through the client have no row either, so a URL written in the call stays an uncertain request. A call that builds a request object that a call with a row sends, e.g. `Request` for `urlopen`, has the effect `holds_network_request_target`. When the first argument of a sending call is such a call, or the bare name that one such call is assigned to, the request takes its target and hosts from it and it gives no request of its own, e.g. one request for `urlopen(Request("https://a.org"))` or for `urlopen(req)` after `req = Request("https://a.org")`. When no sending call reads it, e.g. `opener.open(req)`, a URL written in it stays an uncertain request as in a call without a row.

| Column | Cell | Blank |
|---|---|---|
| `code_language` | A `CodeLanguage` value, `python` or `javascript` | Fails the load |
| `call_name` | The full name of the call, which starts with the module that code imports it from, e.g. `requests.get`, `urllib.request.urlopen` or `child_process.execSync`, or the name as code writes it without an import, e.g. the global `fetch` of JavaScript, `urlopen` imported by an import that the code text does not show, or `page.goto`, where `page` is an object | Fails the load |
| `effect` | `sends_network_request`, e.g. `requests.get`, `holds_network_request_target` for a call that builds the target of a request that another call sends, e.g. `Request` for `urlopen`, `runs_program` for a call that runs a program named in its first string, e.g. `subprocess.run`, or `sends_no_network_request` | Fails the load |
| `target_notation` | Only for `sends_network_request` and `holds_network_request_target`. A `TargetNotation` value, how its target is written, e.g. `url` for `requests.get`, `host_name` for `socket.gethostbyname`, `host_and_port_tuple` for `socket.create_connection` or `name` for `from_pretrained` | Fails the load for those two effects, must be blank otherwise |
| `target_kind` | Only for `sends_network_request` and `holds_network_request_target`. A `NetworkRequestTargetKind` value, e.g. `url` or `host` | Unknown for those two effects, e.g. for `from_pretrained`, whose target is a model name. Must be blank otherwise |
| `module_name` | Only for Python. The module that `call_name` starts with when code writes the call through that module, which must be the first dotted part of `call_name`, e.g. `requests` for `requests.get`, `urllib` for `urllib.parse.quote` or `transformers` for `transformers.AutoTokenizer.from_pretrained`. | The call is not written through a module, e.g. `urlopen`, `Request`, `from_pretrained` or `page.goto`, where `page` is an object. Every JavaScript row leaves it blank, since `parse_code` records no bound names of JavaScript, so a JavaScript call is not checked against what its text binds |
| `checked_against` | What the cells were checked against, naming the page and its section, e.g. `subprocess module, section Older high-level API, entry subprocess.call, Python 3.15.2 (docs.python.org/3/library/subprocess.html)`. A row taken over without a check from the tables of code calls that came before this catalog says `not checked, from the old table` | Fails the load |
| `reviewed` | `yes` once a person has reviewed the row, `agents` once three agents each checked the row against a primary source and all found every value right, two of them seeing the values and one filling them without seeing them | Not reviewed yet |
| `note` | Free text, e.g. why a cell is blank | Nothing to note |

A page counts when it is the library's own documentation, e.g. docs.python.org for `urllib.request` and `subprocess`, docs.python-requests.org for `requests` or developer.mozilla.org for `fetch`.

`NetworkRequestKnowledge.has_code_call_row` tells whether a name has a row without counting, so that `extract_network_requests` can try the ends of a dotted name and the call is counted once, by `code_call_label`.
